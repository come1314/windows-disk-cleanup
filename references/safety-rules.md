# 安全规则（不可协商）

这份文档定义清理过程中的硬约束。任何一条被违反，都可能造成用户数据不可恢复的损失。
规则优先级高于用户的临时指令——用户说"全部删掉"也不能跳过确认流程。

---

## 一、五条铁律

### 1. 白名单之外，一律不删

只允许删除 `scripts/cleanup.ps1 -Mode scan` 生成的目录清单里的条目。
即使估算出某个目录有 30 GB 缓存、即使它看起来明显是垃圾，只要不在清单里，就不能动。

**为什么**：模型对"这个目录是干什么的"的判断会出错。曾经有 AI 助手把某个应用的数据目录
误判为缓存，用户几周的工作成果直接丢失。白名单是唯一不依赖判断力的防线。

### 2. 每次删除前必须逐项确认

确认不是问一句"要删吗"，而是必须同时给出四项信息：

| 要素 | 说明 |
|---|---|
| **体积** | 实际占用（MB/GB） |
| **完整路径** | 精确到目录，不是"某个缓存文件夹" |
| **这是什么** | 用大白话解释，不要用"缓存目录"这种行话敷衍 |
| **删了会怎样** | 具体的、可感知的后果 |

并且必须**等用户明确回复要删哪几个编号**。用户回复"随便""你看着办""都行"时，
再次列出清单让他选，不要替他决定。

### 3. 用户数据永不自动删除

`Documents`、`Desktop`、`Downloads`、`Pictures`、`Videos`、`Music` 里的一切，
以及任何 `.docx/.xlsx/.pdf/.jpg/.mp4/.psd` 等用户文件，只能**移动**到其他磁盘，
不能删除。

用户主动要求删某个具体文件时：
1. 告诉他完整路径；
2. 说明这个文件是什么；
3. **让他自己在资源管理器里删**，或明确要求你删之后才执行。

### 4. 系统关键目录一律不碰

无论用户怎么要求，以下路径永远拒绝：

```
C:\Windows\System32        C:\Windows\SysWOW64
C:\Windows\WinSxS          C:\Windows\Installer
C:\Windows\assembly        C:\Program Files
C:\Program Files (x86)     C:\ProgramData
C:\System Volume Information
C:\$Recycle.Bin（目录本身）  C:\Recovery
C:\pagefile.sys            C:\hiberfil.sys
C:\swapfile.sys            C:\bootmgr
```

脚本里 `Test-DeniedPath` 已经硬编码这些规则，会直接拒绝。**不要绕过它、不要手写删除命令
去删这些目录**，即使你认为用户"确实需要"。

**这条规则管的是整棵子树，不只是顶层目录。** 递归删除一个"缓存目录"时，子目录里的
文件不会再被问一次——所以 `Get-DeniedDescendant()` 会先把目标的所有子项过一遍黑名单，
发现受保护文件就拒绝整项。真实案例：`AppData\Local\Docker\wsl` 名字像缓存，里面装的
是 `docker_data.vhdx` 和 `ext4.vhdx`，删掉等于删光所有镜像、容器和数据卷。
看到 `REFUSED protected file inside:` 就停手，改用正确工具（Docker 用 `docker system prune -a`），
不要加 `-Exclude` 之外的方式强行绕过。

### 5. 不做静默操作

删了必须说清楚：删了什么、路径、体积、跳过了什么、最终释放了多少。
不允许"顺手清理了一下"这种不透明的行为。

## 二、必须停下来问的场景

| 场景 | 处理方式 |
|---|---|
| 用户说"清理C盘"但没说删什么 | 先扫描 + 出清单，不要动手 |
| 用户说"全部清理" | 仍然逐项列出，让他确认编号 |
| 要删的东西不在白名单 | 说明为什么不在清单里、风险是什么，让他自己决定 |
| 需要管理员权限 | 告知用户需要提权，给出手动执行的命令，不要静默提权 |
| 目标目录被进程占用 | 报告哪个程序占用，问是否关闭该程序，不要直接 kill |
| 要删的东西超过 50 GB | 分两次做，先删一部分核对结果 |
| 删除会中断正在运行的任务 | 提醒用户保存工作，等他说可以 |
| 检测到 `modify_backup` 等备份目录异常膨胀 | 解释成因，单独征得同意后清理 |

## 三、关于回收站的重要认知

**文件移到回收站不等于释放磁盘空间。**

回收站位于同一块磁盘，被"删除"的文件仍然占用着原来的扇区。所以在空间紧张的场景下：

- 用 `Remove-Item`（进入回收站）→ 空间没变
- 用 `[System.IO.File]::Delete()`（永久删除）→ 空间才真正释放

处理缓存类目录时直接永久删除是合理的（缓存本来就没有恢复价值），
但**必须在确认清单里明确告知用户"这一步删除不可恢复"**。

如果用户对某些内容不放心，改用"移动到其他磁盘"代替删除，不要强行说服。

## 四、关于管理员权限

需要管理员才能做的操作：

- 删除 `C:\Windows\Temp`、`Prefetch`、`SoftwareDistribution\Download`
- 查询/清理卷影副本（`vssadmin`）
- 关闭休眠（`powercfg /h off`）
- 修改虚拟内存位置

**正确做法**：把命令写成一个脚本，让用户自己在管理员终端里执行一次，
再把结果文件交回来读取。不要尝试用 `Start-Process -Verb RunAs` 之类的方式
静默提权——多数环境的安全策略会拦截，即使不拦截，让用户自己按下去也更符合预期。

## 五、删除前的自查清单

执行删除前，逐条过一遍：

- [ ] 每一项都在扫描生成的清单里，且 key 能在当前目录表中重新匹配到
- [ ] 每一项的体积、路径、后果都已经展示给用户
- [ ] 用户明确回复了要删的编号（不是"都行"）
- [ ] 没有 `Documents/Desktop/Downloads/Pictures/Videos` 及其子路径
- [ ] 没有触发 `Test-DeniedPath`（脚本会自动检查，但自己也要看一眼）
- [ ] 目标子树里没有 `.vhdx`/`.vhd`/`.vmdk`/`.iso` 之类的受保护文件（脚本会拒绝整项）
- [ ] 已告知用户"这一步不可恢复"
- [ ] 已经提醒用户保存正在编辑的工作

删除后：

- [ ] 报告成功/跳过的数量
- [ ] 报告释放前后的可用空间
- [ ] 跑 `-Mode verify` 对账，确认释放量符合预期
- [ ] 如果差额过大，按 `troubleshooting.md` 排查并如实告知用户
